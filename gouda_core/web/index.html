PREP発進準備シーケンス
  1. 1waypoint セットを選ぶ（地図はセットに保存された変換後地図と組になる） waypoint タブ「AUTO 自律走行の準備」→ セットを選んで「プレビュー」
  2. 2初期位置・向きを入れる（IFD-39、map frame） 同じ欄の x・y・向き、または「地図のクリックで初期位置を置く」
  3. 3自律走行開始ボタンを 1 回押す（追加の承認は挟まない: RQ-I011） 右上の「自律走行」
  4. 4自律走行系の起動（ND-08 → ND-07 → ND-10。TR-05） 操作なし（ボタンの後に自動）
「自律走行」を押すと、mode manager が ND-08（オドメトリ）を起動し、地図を ND-07（自己位置推定）に読ませ、推定が正常になってから Nav2 を起動する。速度上限の適用と走行禁止のマスクを確かめてから motion_hold を解いて走り出す。
推定が正常にならない間（LiDAR の点群がないなど）は走り出さない。GNSS による初期位置（DEC-124）は未実装なので、初期位置は手で入れる。
各段の成立は「運行」タブの mode/state と DecisionEvent で確認する。架空の値は表示しない。

MC不感帯の補償（gouda_motion_controller、DEC-171 案 A）
自律走行の指令（Nav2 の cmd_vel を正規化した倒し量 r）だけにかかる。手動（ゲームパッド）には影響しない。向きごとに、r がしきい値未満なら中立のまま、しきい値以上なら 最低倒し量＋(1−最低倒し量)×r を出す。値は 0 以上 1 未満の倒し量（1 が倒し切り）。前進・後退は前後の軸、旋回は左右とも同じ値。
保存するとすぐに反映する（自律走行中も、次の指令から）。最低倒し量としきい値のどちらかが UNKNOWN の向きは補償しない（倒し量をそのまま出す）。値は実測で決める（推測で埋めない）。

recovery の回数：BT が失敗を返して一時停止（TR-07、計画の失敗）するまでの後退・再計画の回数。1 以上 PRM-18 以下の整数。inflate_around_unknown：true か false。どちらも UNKNOWN（空欄）なら正本の値（PRM-18・PRM-98）を使う。
保存した値は、次に gouda.sh start したときから使う（走行中・今の起動の中の次の走行には効かない：DEC-207 (a)）。
