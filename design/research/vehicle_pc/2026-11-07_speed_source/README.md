# 速度の帰還に使う実速度の比較（2026-11-07、第216便）

- 目的：ND-11 の速度の帰還（REV-241）の実速度に、どちらを使うかを決める。
  - (A) 2 つの姿勢の差（今の IFD-25。ND-08 の中継が出す）
  - (B) GLIM の v_world_imu（GLIM 1.2.2 が ~/odom の twist.linear に出す値。odom 座標、線速度だけ）
- データ：第210便の手動走行（records/20261107_005310 の bag_01・bag_02）と、同時に動いた地図作成の GLIM の dump。
  - dump の中身：odom_imu.txt・odom_lidar.txt・traj_imu.txt、000000/data.txt の各フレームの v_world_imu
  - 生データはリポジトリに入れない。車載 PC から読むだけで写した
- スクリプト：`load.py`・`explore.py`・`analyze_cmp.py`・`b2_steady.py`。出力は `out_b1.txt`・`out_b2.txt`・`out_b1_lpf.txt`・`out_b2_steady.txt`。
- 注意：dump の値は、GLIM の固定ラグ平滑化（smoother_lag 5.0 s）の後の推定値。走行中に配信される値（その時点より後のデータなし）とは違う。配信の遅れ（壁時計とスタンプの差）は、このデータでは測れない。

## 結果（前進の速度、mm/s）

| 項目 | (A) 今の中継 | (B) v_world_imu |
|---|---|---|
| 静止の sd（bag_01 / bag_02） | 1.90 / 1.58 | 1.71 / 1.70 |
| 定常走行の sd（トレンド除去、前進 1・前進 2・後退 1） | 4.2・4.0・4.1 | 4.2・4.5・4.6 |
| 遅れ（相互相関） | B より 55 ms（bag_01）・50 ms（bag_02）遅い | 基準 |
| 動き出しで 0.03 m/s を越えるまで（IMU の積分が基準、7 回の平均） | +129 ms | +90 ms |

- 旋回の速さ：(A) の yaw の速さは、IMU の gz より 45〜51 ms 遅い。振幅の比は 1.0017。
- (A) の遅れは、後ろ向きの差分を新しい方の時刻で打つことによる半区間分（約 50 ms）と読める。中心差分にすると (B) との差は 1〜2 ms。
- 走行の向きは、IMU・LiDAR の −y から約 9° ずれている（横の速度が前進の −0.155 倍）。/config の取付の yaw 0.1745 rad（10°）と合う。base_link の速度は、この取付で直っている。

## 決めたこと（第216便）

- 最初の実車は (A)（IFD-25 のまま）を使う。
  - 差の 50 ms は、車体の動き出しの遅れ（0.47〜0.76 s）の約 1 割。
  - (B) は新しい IF と、座標・IMU の位置の補正が要る。
  - 配信の値では確かめていない。
- 低域の通過は入れない。定常の sd 約 4 mm/s は、P のゲイン 0.5（倒し量/(m/s)）で約 0.002 の倒し量にしかならない。
- (B) と IMU の gz を使う案は K-yama-20/tsukuba-autonomous-robot#83。
