## 読むために記録に要るもの

停止距離は「止める合図の時刻」と「その前後の車体の位置」から出す。どちらかが記録にないと出せない（未判定になる）。

| 走らせ方 | 止める合図 | 位置 | 解析の指定 |
|---|---|---|---|
| 自律走行（停止点、待機ボタンなどで止める） | `control/motion_hold` が true に変わった時 | `localization/odometry`（rosbag の中） | `--trigger hold --track odom.csv` |
| 手動操作を事前地図作成モードで記録（第210便と同じ取り方） | `/esp32/status` の applied_y が 0 になった時（スティックを戻した時） | GLIM の軌跡 `odom_lidar.txt`（地図の `source/` に残る） | `--trigger neutral --track odom_lidar.txt` |

- 手動走行モードだけの記録（GLIM が動いていない）には位置がない。IMU の加速度の積分は傾きで使えなかった（第210便）ので、この解析では使わない
- 手動操作の「止める合図」は applied_y が 0 になった時刻で、スティックを戻し始めた時刻ではない。ゆっくり戻すと、戻している間に進んだ分は停止距離に入らない
- 自律走行の停止（PC が中立を指令）と手動の停止（ゲームパッドを離す）は、ESP32 までの経路が違う。同じ d になるかは未確認

## 使い方

```
# ROS 2 Jazzy のある計算機で（rosbag2_py が要る）
python3 extract.py <rosbag のフォルダ> <出力のフォルダ>

# どこでも（ROS は要らない）
python3 stop_distance.py <出力のフォルダ> --trigger hold --track <出力のフォルダ>/odom.csv --json result.json
python3 stop_distance.py <出力のフォルダ> --trigger neutral --track <地図のフォルダ>/source/odom_lidar.txt --json result.json
```

合図ごとに次を出す。

| 列 | 意味 |
|---|---|
| 直前の速さ | 合図の直前 0.5 s（`--pre-s`）の平均の速さ。位置の差から出す |
| 停止距離 | 合図の時の位置から止まった位置までの、進行方向の距離 |
| 横 | 同じく横の距離 |
| 止まるまで | 合図から、位置が止まった位置の 0.02 m（`--eps-m`）以内に収まり続けるまでの時間 |
| 止まった後の動き | 窓の最後 1 s（`--tail-s`）の中で、止まった位置から最も離れた距離（揺れの目安） |
| 判定 | 算出／未判定（未判定は理由つき。値を推測で埋めない） |

- 止まった位置は、合図から 6 s（`--window-s`）か次の動き出しまでの窓の、最後 1 s の位置の中央値
- 0.5 s・6 s・1 s・0.02 m は解析の条件の既定値で、車体の値ではない。結果の 1 行目に使った条件が出る
- 自律走行の停止点で止まった合図には、記録 `rule_stop_hold` の停止点の番号と、判定した時の停止点までの距離が付く

## 限界（結果を読むときに）

- 時刻は header.stamp を使う。GLIM の位置の時刻と PC の時計のずれ、位置が出るまでの遅れは直していない。ずれが L 秒あると、停止距離は 速さ × L だけずれる
- 位置は 10 Hz 程度（GLIM）。0.02 m より小さい動きは「止まっている」とみなす
- 進行方向は合図の直前 0.5 s の動きの向き。曲がりながら止まると、進行方向と横の分け方が粗くなる
- 床の傾き、路面、積載、電池の状態は記録に入らない（人の記録に頼る）
