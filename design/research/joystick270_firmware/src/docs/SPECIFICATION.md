## 1. 目的と範囲

今仙技術研究所の電動車椅子 EMC-270 に対し、純正ジョイスティックのX/Y電圧を
リレーで切り替え、ESP32とMCP4922が生成した電圧で走行指令を与える。

本仕様の範囲は次のとおり。

- X軸: 左右。負が左、正が右。
- Y軸: 前後。負が後退、正が前進。
- X/Yは独立で、入力範囲は正方形 `[-1,+1] × [-1,+1]` とする。
- 速度切替、ホーン、電源ボタンは制御しない。
- 人が設定した方向別端点を保存する。端点は自動探索しない。
- 車両が動かない電圧範囲を、左右輪速度を使って自動探索する。
- Ubuntu 24.04 / ROS 2 Jazzy車載PCとはUSBシリアルで通信する。
- 車両エンコーダーは別ESP32が解析し、左右輪速度を3.3 V UARTで送る。

## 2. 情報の確度

### 2.1 確認済み

- ESP32: ESP32-DevKitC-VE、ESP32-WROVER-E、フラッシュ8 MB。
- DAC: MCP4922-E/P。実装予定。
- ADC: AE-ADS1015。EMC側へ実際に出たX/Y電圧の監視用。
- リレー: TQ2-5V。実装予定。
- 中央基準: MCP6002でX/Y別にバッファした約2.5 V。
- EMC側で測った電源電圧: 4.99 V。動作中変動は未測定。
- 純正ジョイスティックの写真上の線色は、自作基板のX/Y定義には使用しない。
- 写真では黒・黄・赤の系統が左右、黒・黄・橙の系統が前後。

### 2.2 未決定（UNKNOWN）

- `x_negative_mv`、`x_positive_mv`、`y_negative_mv`、`y_positive_mv`。
- 実エンコーダーの分解能、更新周期、速度ノイズ。
- 停止判定10 mm/sが実車に適切か。
- 中央誤差、停止時間、電圧誤差の最終受入値。
- Ubuntu実機のUSB `/dev/serial/by-id/...`。
- 車両走行中の4.99 Vレール変動。

### 2.3 矛盾または未確認（CONFLICTED）

- 断線検出はないとの推定がある一方、テスター接続時にE-06、ビープ、
  モーター停止が発生した記録がある。入力負荷、接触、測定モードのどれが原因かは
  未確定であり、断線・異常検出がないとは断定しない。
- 保存済みBOMの旧版にはJ1-1を5 Vとする記述があるが、現行回路ネットリストでは
  J1-1は未接続である。本実装は現行ネットリストを正とする。

## 3. 現行回路との対応

### 3.1 ESP32ピン

| 機能 | ESP32 GPIO | 回路ネット／端子 |
|---|---:|---|
| MCP4922 CS | 5 | `GPIO5_CS_N` |
| MCP4922 SCK | 18 | `GPIO18_SCK` |
| MCP4922 MOSI | 23 | `GPIO23_MOSI` |
| リレー駆動 | 32 | `GPIO32_RELAY` |
| ADS1015 SDA | 21 | `I2C_SDA` |
| ADS1015 SCL | 22 | `I2C_SCL` |
| 速度UART RX | 33 | J11-3 |
| 速度UART TX | 13 | J11-4 |
| UART GND | - | J11-1 |
| 3.3 V（通常は接続しない） | - | J11-2 |
| 予備 | 4、19 | J11-5、J11-6 |

J11をUARTに使うとき、SW1はCOMM側としてLEDアノードを切り離す。GPIO4は
ストラップ機能を持つためUARTには使用しない。別ESP32と電源を共有しない場合、
J11-2同士を接続せず、GND、TX、RXだけを接続する。

### 3.2 EMC/ジョイスティック端子

| 端子 | 現行ネット |
|---|---|
| J1-1 | 未接続 |
| J1-2 | GND |
| J1-3 | `JOY_Y_WIPER` |
| J1-4 | `EMC_Y_ACTUAL` |
| J1-5 | `EMC_X_ACTUAL` |
| J1-6 | `JOY_X_WIPER` |
| J2-1 | GND |
| J2-2 | `EMC_X_ACTUAL` |
| J2-3 | `EMC_Y_ACTUAL` |

JP2/JP3はリレー非励磁時の入力源を選ぶ。

- 2–3短絡: 純正ジョイスティックへ戻る。
- 1–2短絡: MCP6002の固定中央電圧へ戻る。

通常運用の既定は2–3短絡とする。JP1はリレーのAUTO ARM電源許可である。

### 3.3 電源とUSB断

現行ネットリストでは基板の+5 VはESP32開発ボードの5 Vピンから供給され、J1-1は
未接続である。USBコネクタが物理的に抜けるとESP32とリレー電源が失われ、リレーは
非励磁側へ戻る。再接続後はESP32が再起動し、NVS設定を読み、PCとの新しい
ハンドシェイク後に自動復帰条件を再評価する。

## 4. 電圧生成と監視

### 4.1 MCP4922

- SPI MODE 0、1 MHz、MSB first。
- VREFは約2.5 V、ゲインは2倍（GA=0）。
- XはDAC A、YはDAC B。
- LDACはGND固定のため、X/Yは連続して書くが厳密な同時更新ではない。
- `dac_full_scale_mv`の初期候補は4990 mV。
- 12 bitコードは `round(mV × 4096 / dac_full_scale_mv)` とし、0～4095へ制限。

MCP4922は書込み専用で、SPI通信の読み戻しはできない。出力異常はリレー投入後の
ADS1015値から間接的に通知する。

### 4.2 ADS1015

- I²Cアドレス: `0x48`。
- A0: `ADC_X`、A1: `ADC_Y`。
- PGA: ±4.096 V、1600 SPS設定。
- 回路上は10 kΩ/10 kΩ分圧の後に1 kΩと10 nFのフィルタがある。
- ADCピン電圧を2倍してEMC側電圧mVへ戻す。
- ADS1015の量子化はADC入力側約2 mV、EMC換算約4 mVである。

DAC探索刻み2 mVは生成できるが、ADS1015単独ではその差を毎回識別できない。
中央境界の主判定は車輪速度で行い、ADS1015は出力監視に使う。

### 4.3 リレー投入前確認の制約

ADS1015はリレー共通接点 `EMC_X_ACTUAL` / `EMC_Y_ACTUAL` を監視する。リレー
非励磁時には純正ジョイスティック側を読むため、DACの実電圧を投入前に測れない。

実装するシーケンスは次のとおり。

1. 設定値、範囲、通信状態を検査。
2. リレー非励磁のままDACへ中央値を書込む。
3. 20 ms待つ。
4. リレーを励磁する。
5. 30 ms待ってADS1015で実出力を確認する。
6. 中央目標から許容差を超えた場合は直ちにリレーを解除し、目標値・実測値・理由をPCへ送る。

真の投入前実測が必要なら、基板へDAC X/Y専用ADC配線または独立コンパレータを
追加する必要がある。これはファームウェアでは解決できない。

リレー状態はGPIOへ出した指令値であり、接点の位置を直接読むフィードバックではない。
純正ジョイスティックが中央にあると、接点が切り替わらなくてもARM直後のADC値が目標と
一致する可能性がある。その場合は走行指令を変えた後の目標・実測差で初めて検出される。

## 5. 保存設定

端点値に安全な仮既定値は設定しない。次の全項目をPCから登録するまで通常ARMを
拒否する。

| 項目 | 意味 | 初期候補 |
|---|---|---:|
| `x_negative_mv` | 左端 | REQUIRED |
| `x_positive_mv` | 右端 | REQUIRED |
| `y_negative_mv` | 後退端 | REQUIRED |
| `y_positive_mv` | 前進端 | REQUIRED |
| `x_seed_mv` | X中央探索開始値 | 2500 mV |
| `y_seed_mv` | Y中央探索開始値 | 2500 mV |
| `dac_full_scale_mv` | DAC換算フルスケール | 4990 mV |
| `watchdog_ms` | PC指令監視 | 300 ms |
| `slew_full_scale_ms` | 0から最大までの通常遷移時間 | 1000 ms |
| `motion_threshold_mm_s` | 各輪の停止判定上限 | 10 mm/s |
| `output_warn_tolerance_mv` | 通常走行時の出力差通知 | 40 mV |

設定はNVSの`cfg_a`と`cfg_b`へ世代番号とCRC付きで交互に保存する。起動時はCRCと
内容が有効な最新世代を選ぶ。端点は保存済みでも中央探索が未完了なら通常ARMを
拒否する。

## 6. 中央無動作範囲の較正

### 6.1 入力条件

- PCから明示的な較正開始要求がある。
- 方向別4端点とX/Y開始値が有効である。
- USB指令が300 ms以内で継続している。
- 速度UARTが200 ms以内に更新され、`VALID`ビットが立っている。
- ADS1015が使用可能である。
- LittleFSログ領域が使用可能である。
- 左右輪速度の絶対値が閾値以下である開始値を使用する。

速度は単一車速ではなく左右輪別に使う。片輪でも閾値を超えれば「移動」とする。
これにより、その場旋回を停止と誤判定しない。

### 6.2 探索方法

1. X/Yを開始値へ設定し、リレー投入後確認を行う。
2. X左、X右、Y後退、Y前進の順に探索する。
3. 対象外の軸は開始値に固定する。
4. 各候補電圧変更後250 ms待つ。
5. 移動がなければ、左右輪が連続2秒間閾値以下になるまで待つ。
6. 20 mV刻みで端点方向へ進み、移動を3サンプル連続で検出する。
7. 最後に停止した値と最初に移動した値の間を二分し、2 mV以内まで絞る。
8. 各方向を3回測定する。
9. 3回すべてで停止した範囲の共通部分をX/Y別の中央範囲とする。
10. 中央範囲の中点を正規化指令0の出力値として保存する。

開始値で車輪が動く、端点まで動かない、速度UARTが途絶する、PC指令が途絶する、
10分を超える、ログを書けない場合は較正を失敗または中断する。

## 7. 通常制御

- PC指令はX/Yそれぞれ`-1.0～+1.0`。
- X/Yは独立して制限し、円形正規化は行わない。
- 中央から正端、中央から負端を別々に直線補間する。
- 軸反転設定は設けない。
- 通常指令はフルスケール1000 msのスルーレート制限を通す。
- 300 ms指令途絶時はスルーレートを迂回し、DACを即時中央へ書き、10 ms後にリレーを解除する。
- ESP32内に保存される「既定値」は、端点・中央範囲・監視値である。走行軌跡や
  自律走行シーケンスは保存しない。

## 8. モード

| モード | 意味 |
|---|---|
| `BOOT_SAFE` | 起動直後。リレー非励磁 |
| `MANUAL_SAFE` | 有効な較正値がなく、純正ジョイスティック側 |
| `READY` | 有効設定あり。自動操縦待機 |
| `ARMING` | DAC中央を書込み、リレー投入後確認中 |
| `DRIVE` | 正規化指令を出力中 |
| `CALIBRATING` | 中央無動作範囲を探索中 |
| `FAILSAFE` | PC指令途絶などで中央化・リレー解除済み |

通常ARMとUSB再接続後の自動復帰では、CRC正常な指令を受け、正規化X/Yが中央付近で
500 ms継続してからリレーを投入する。ROS 2ドライバは接続を失う前のARM要求を保持し、
タイマやUSBのジッタを見込んで再接続後に中央指令を600 ms送り、その後に最新の新鮮な
上位指令へ戻す。

ARM直後の実測不一致や較正の失敗・中断では`rearm_required`を立て、ARM=trueが流れ
続けても再試行しない。再開にはPCから明示的なARMサービスを送るか、上位指令を一度
ARM=falseにしてからtrueへ戻す。通常走行中の単純なUSB瞬断、ESP32再起動、PC指令
watchdogからの復帰ではこのラッチを立てず、自動復帰を許可する。

## 9. 異常時動作

| 条件 | 動作 |
|---|---|
| PC指令が300 ms途絶 | 即時中央、10 ms後リレー解除、PCへ理由通知 |
| 通常走行中の速度UART途絶 | 走行継続、警告と経過時間を通知 |
| 較正中の速度UART途絶 | 較正中止、中央、リレー解除、ログ保存 |
| 通常走行中のADC読取り失敗 | 走行継続、警告通知 |
| 通常走行中の目標・実測差 | 走行継続、両値と警告通知 |
| ARM直後の中央実測不一致 | リレー解除、`rearm_required`、ARM失敗通知 |
| 較正中のUSBリンク断 | 較正継続を禁止し、PC側イベント`32769`で再開始・再ARM要求を通知 |
| 有効設定なし／NVS破損で起動 | ARM拒否、純正ジョイスティック側 |
| NaN/Infを含むROS指令 | PCドライバが拒否してDISARM送信 |
| USBシリアル書込みが50 ms詰まる | 接続を閉じ、再接続処理へ移行 |
| 設定端点を越える指令 | 保存端点へ制限、状態通知 |
| ESP32リセット／USB電源断 | ハードウェアによりリレー非励磁へ戻る |

非常停止はEMC-270の独立電源ボタンを用い、ESP32ソフトウェアへ依存しない。

## 10. ログ

PCが較正開始を受理した時点から、ARM確認を含めて較正終了・失敗判定まで20 msごとに
次を記録する。

- ESP32時刻、セッションID、サンプル番号
- 探索段階、軸、方向、測定回、判定
- DAC目標X/Y
- ADS1015実測X/Y
- 左右輪速度
- 連続停止時間
- 失敗・中断理由

同じフレームをUSBへストリームし、ESP32のLittleFS
`/calibration.frames`にも保存する。ROS 2ドライバはCSVへ保存する。USB断後は
`recover_log`サービスでLittleFS上のバイナリフレームを回収できる。変換には
`tools/decode_calibration_log.py`を使う。

## 11. 通信

- PC USB-UART: 460800 bps、8N1。
- エンコーダーESP32 UART: 230400 bps、8N1、50 Hz標準。
- 全フレームに同期語、版、種別、長さ、シーケンス、送信側時刻、CRC-16を付ける。
- 詳細は [`PROTOCOL.md`](PROTOCOL.md) と
  [`ENCODER_UART.md`](ENCODER_UART.md) を参照。

## 13. 実車投入前ゲート

次が未完了の間、実車安全性を確認済みとは扱わない。

1. 基板単体の5 V/3.3 V、SPI、I²C、リレー極性確認。
2. リレー非励磁・ADC監視だけをEMC-270へ接続し、E-06が出ないことを確認。
3. ADS1015の約20 kΩ入力負荷がEMC-270診断へ影響しないことを確認。
4. JP2/JP3の非励磁側とJP1の動作を導通測定で確認。
5. 人を乗せず、車体を固定または安全な空き地で中央・端点方向を確認。
6. USB抜去、ROSノード停止、速度UART停止、ESP32再起動の挙動を確認。
7. 実測値から停止判定閾値、許容電圧差、最終受入基準を決定。
