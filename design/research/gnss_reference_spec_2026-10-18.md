# GNSS（デュアルアンテナ・ネットワークRTK）活用 実装仕様まとめ

## 0. 本書の扱い

- 本書に出てくる名称と数値は、**すべて参考値**です。実装する環境やパッケージに合わせて決めてください。
  - 名称：座標系名、TFフレーム名、パラメータ名、トピック名、ノード名、サービス名、状態名
  - 数値：閾値、監視時間、サンプル数、許容誤差、精度の目安、受け入れ基準
- 表中の「（参考）」は、上記の扱いをあらためて示すための表記です。
- 実機の仕様（アンテナ間隔0.6mなど）は実測値です。ただし、それをもとに決める判定の閾値は参考値です。

## 1. 目的

- LiDAR事前地図の座標系と、GNSSの絶対座標系（局所ENU）を対応付ける
- GNSSの位置と方位から初期姿勢を自動で与え、NDTの初期収束の失敗をなくす
- 走行中にNDTが発散していないかを監視し、発散したら再初期化する

## 2. 前提

- 事前地図：IMUと3D LiDARで作成する（Z軸は重力方向に揃っている前提）
- 自己位置推定：NDT系（ROS 2）
- GNSS：ネットワークRTK、デュアルアンテナ（アンテナ間隔0.6m、実測値）
  - 方位精度の目安：0.2〜0.5°（参考）
  - 静止状態で方位を取得できる

## 3. 座標系とTF構成

| 親 → 子（名称は参考） | 種別 | 発行元 |
|---|---|---|
| `enu` → `map` | static TF | オフライン校正の結果（T1） |
| `map` → `odom` | 動的 | NDT |
| `odom` → `base_link` | 動的 | オドメトリまたはEKF |
| `base_link` → `gnss_main` / `gnss_sub` | static TF | 実測したアンテナ取付位置 |

- 局所ENUは、基準点（緯度・経度・高さ）を原点とし、東・北・上を軸とする接平面座標系です。
- 平面直角座標系やUTMは原則として使いません。使う場合は子午線収差の補正が必要です。

## 4. パラメータ（地図ファイルとまとめてバージョン管理する）

| パラメータ名（参考） | 内容 |
|---|---|
| `lat0`, `lon0`, `h0` | 局所ENUの基準点 |
| `map_to_enu_x/y/z/yaw` | T1で求める変換。p_enu = R·p_map + t |
| `ant_x/y/z` | `base_link`から見た主アンテナの位相中心の位置 |
| `mount_yaw_offset` | `base_link`のx軸から見た「主→副アンテナ」方向の角度（T2で求める） |
| `heading_frame` | 受信機が出力する方位の定義（北0・時計回り、または東0・反時計回り） |
| 品質判定・監視の閾値 | 7章・8章を参照 |

- 地図を作り直したら、T1とT2もやり直します。

## 5. 方位の変換手順

1. 受信機の出力：ψ_NED（真北から時計回り）
2. ENUへの変換：ψ_ENU = π/2 − ψ_NED
3. 地図座標系への変換：ψ_map = ψ_ENU − map_to_enu_yaw
4. 車体座標系への変換：ψ_base = ψ_map − mount_yaw_offset

- 方位は真北基準なので、磁気偏角は補正しません。
- 受信機やドライバがすでにENU定義で方位を出力している場合は、手順2を省きます。

## 6. 実装タスク

### T1：地図座標系とENUの変換推定（オフライン、地図ごとに1回）

1. 事前地図上で初期姿勢を手動で与え、NDTが収束したことを目視で確認する
2. コース全体を曲がり角も含めて走行し、以下を記録する
   - NDTの姿勢
   - GNSSの位置
   - GNSSの方位
   - TF
3. 次の条件をすべて満たす時刻のデータだけを、対応点として抽出する
   - GNSSがRTK Fixである
   - NDTのスコアが良好である
   - 特徴が少なくNDTが退化しやすい区間ではない
4. NDTの姿勢をGNSSの時刻に補間し、レバーアーム補正でアンテナ位置に換算する
   - p_ant_map = p_base_map + R_base_map · l_ant
5. RANSACで外れ値を除き、最小二乗法（SVD）で4自由度（x, y, z, yaw）を推定する
   - 縮尺は1に固定する
   - yawは位置の対応だけから推定する（方位データは使わない）
6. 出力
   - 変換パラメータ
   - ENU→地図座標系のstatic TF

### T2：アンテナ取付オフセットの校正

- NDTが収束している区間で、「GNSS方位から求めた地図座標系のYaw」から「NDTのYaw」を引き、その円周平均をとる
- T1で求めたyawを固定してから行う（T1とT2の誤差を区別するため）
- ハードウェア側で確認すること
  - 2本のアンテナが同じ型番で、コネクタの向きが揃っている
  - グランドプレートが付いている
  - 受信機にアンテナ間隔（基線長）を設定してある

### T3：初期姿勢ノード（ノード名は参考：`dual_antenna_initial_pose`）

- 入力（トピック名・型は参考）
  - GNSS位置：`/fix`（`NavSatFix`）
  - GNSS方位：`/gnss/heading`（`Imu`型。独自メッセージの場合は変換ノードを用意する）
- 出力（トピック名は参考）
  - `/initialpose`（`PoseWithCovarianceStamped`）
  - 使うNDTパッケージが初期姿勢を受け取る方法に合わせる
- 状態遷移（状態名は参考）
  1. WAIT_FIX：位置と方位の両方がFixになるまで待つ
  2. SAMPLE：静止状態でN個のサンプルを集める
     - 方位は円周平均、位置は平均をとる
  3. PUBLISH：レバーアーム補正をしてから、共分散を付けて配信する
  4. VERIFY：一定時間、8章の判定基準を満たすか確認する
  5. TRACKING：通常走行に移る
     - VERIFYで失敗した場合はSAMPLEに戻る
- 再初期化用のサービスを用意する（名称の参考：`~/reinitialize`、型：`std_srvs/Trigger`）
- 傾斜地向けの拡張：roll/pitchをIMUで埋め、3Dのレバーアーム補正にする

### T4：走行中の監視と再初期化

- 発散の判定：以下の(1)または(2)が一定時間続き、**かつ**(3)が成り立つ場合に発散とみなす
  1. NDTの位置とGNSS位置の差が閾値を超える
  2. NDTのYawとGNSS方位の差が閾値を超える
  3. NDTのスコアが劣化している
- (3)を必須にする理由：GNSS側の誤Fixだけで自己位置がリセットされるのを防ぐため
- 発散時の動作：停止 → 再初期化サービスを呼ぶ → T3の手順で初期化する

### T5（任意）：EKFでの融合

- `robot_localization`などのEKFに、次の3つを入力する
  - NDTの姿勢
  - RTKの位置
  - GNSS方位（絶対Yaw）
- 位置と方位は別々に品質判定し、それぞれ独立に融合をオン・オフする

## 7. 品質判定（数値はすべて参考）

| 対象 | 採用条件 | 参考値 |
|---|---|---|
| 位置 | RTK Fix、かつ水平方向の標準偏差が閾値以下 | 3cm |
| 方位 | 方位の解がFix、かつ標準偏差が閾値以下 | 1° |
| 方位（誤Fix対策） | 受信機が算出した基線長と実測値との差が閾値以内 | 数cm |
| 方位（整合性） | 基線方向の傾きとIMUの傾きの差が閾値以内 | 数度 |
| 静止判定（方位） | サンプル間のばらつきが閾値以内 | 0.5° |
| 静止判定（位置） | サンプル間のばらつきが閾値以内 | 3cm |
| 時刻同期 | 位置と方位のタイムスタンプの差が閾値以内 | 0.1s |
| サンプル数 | SAMPLE状態で集める数 | 20 |

- `NavSatFix`のステータスだけではFixとFloatを区別できないことが多いため、ドライバ固有のRTK状態を使います。

## 8. 監視・判定の閾値（数値はすべて参考）

| 項目 | 参考値 |
|---|---|
| 発散判定：位置の差 | 1.0m |
| 発散判定：Yawの差 | 3° |
| 発散判定：継続時間 | 3s |
| VERIFY：GNSS位置との差 | 0.3m |
| VERIFY：GNSS方位との差 | 3° |
| VERIFY：確認時間 | 数秒 |
| NDTスコアの閾値 | 使うパッケージの指標に合わせて決める |

## 9. 受け入れ基準（数値はすべて参考）

| 項目 | 参考基準 |
|---|---|
| T1の水平残差 | RMSが数cm〜十数cmで、場所による偏りがない |
| 方位の残差（GNSS方位 − NDTのYaw − 取付オフセット） | 1°未満で安定している |
| 初期化 | スタート地点で静止した状態から自動で収束する（成功率を記録する） |
| 検証方法 | T1とは別の日の走行データで残差を確認する |

- 残差が走行距離とともに増える場合や、特定の区間に偏る場合
  - 地図のゆがみ、またはNDTの退化を疑う
  - 必要なら、GNSSを拘束に加えて地図を作り直す

## 10. 注意事項

- 測地系
  - ネットワークRTKの座標はJGD2011基準です。
  - 外部の座標と比べる場合は、ITRFとの差（1m以上になることがある）に注意します。
- 高さ：楕円体高と標高のどちらを使うかを統一します。
- 時刻同期
  - GNSSとROSの時刻を同期させます（PPS/NTPなど）。
  - 例：1m/sで走行中に0.1sずれると、10cmの位置誤差になります。
- バージョン管理：地図ファイルと変換パラメータは、必ず同じバージョンとして扱います。

## 11. 実装前に確認する事項

- ドライバが方位をどの形式で出力するか（メッセージ型、NEDかENUか）
- 2本のアンテナの配置（前後か左右か）
- NDTパッケージが初期姿勢をどのように受け取るか（トピックかサービスか、その名称）
- ドライバが基線長とRTK状態を出力しているか
- 各名称と各閾値を、実際の環境に合わせて確定すること
