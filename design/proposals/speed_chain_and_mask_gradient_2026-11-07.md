# 提案：速度の値を 1 本の鎖にし、速度マスクの帯の外に勾配を付ける（第258便）

状態：提案（承認待ち）。実装していない。値はすべて推奨値で、確定は人の判断。

## 0. 人の指示（原文）

- 「なぜ角の直前で、速度の下限が 0.27 → 0.675 m/s に跳ね上がることが起こるのか？これは設計不良であるから修正したい。修正案を考えて提示せよ」
- 「"「最高速度」が 2 つあり、整合の決まりがない"というのは設計の不良であるから、小手先の修正ではなく、まずここを根本的に解消すべき。また、マスクの帯の外が制限無しなのはまずい。勾配をつけてゆっくりな速度にすべき。修正案を提示せよ」

## 1. 今の設計の問題（コードと生成物で確かめた事実）

| 値 | 今の意味 | 今の値 | 使われ方 |
|---|---|---|---|
| PRM-39 | 倒し切りの速度（車椅子側の上限） | 1.25 m/s | 指令→倒し量の正規化。waypoint の区間の制限の既定値 |
| PRM-66 | velocity_smoother の前進の上限 | 1.25 m/s | Nav2 の最終段の上限 |
| PRM-131 | MPPI の vx_max | 0.5 m/s | MPPI の候補の上限（基準値） |
| PRM-162 | MPPI の vx_min | 0.27 m/s | 不感帯より上に指令を保つ下限 |
| PRM-132／PRM-67 | MPPI の wz_max／smoother の旋回の上限 | 0.5 rad/s | |
| PRM-73 | 旋回の角加速度の上限（MPPI の az_max にも使う） | 0.5 rad/s² | |
| PRM-19／PRM-20 | 速度マスクの帯の半幅／刻み | 1.0 m／0.05 m/s | 帯の外は 0＝制限なし |

- (a) 「最高速度」が 3 つ（PRM-39・PRM-66・PRM-131）あり、互いの関係に決まりがない。区間の制限の既定値が PRM-39（1.25）なので、PRM-131（0.5）を超える。
- (b) 上流の MPPI は絶対値の速度制限を `制限 ÷ vx_max` の比率で vx_max・vx_min・wz_max の 3 つに掛ける。比率が 1 を超えると引き上げる（別のセッションの上流ソースの読み。nav2_mppi_controller 1.3.13 optimizer.cpp 504〜510 行。本便では未確認）。1.25 ÷ 0.5 = 2.5 で、vx_min 0.27 → 0.675 m/s、wz_max 0.5 → 1.25 rad/s。
- (c) 速度マスクの帯（半幅 1 m）の外は 0＝制限なしで、MPPI は基準値に戻る。帯に入る瞬間に (b) が発動する。帯の判定は global costmap の更新（1 Hz）ごとなので、切り替わる位置は 1 秒分ばらつく。
- (d) 下限が MPPI の中にあるため、MPPI は「止まる」「その場で向きを変える」を出せない。曲がれる軌道がないとき（Optimizer fail）も下限で前進する（第251便の不合格の本で観測。上流の失敗時の出力の仕組みは未確認）。
- 結果：最高速度を 0.8 → 0.5 に下げた変更（DEC-490）が、最低速度を 0.42 → 0.675 m/s に上げた。角の手前で発動し、外側の壁に衝突した（第251便、issue #102）。

## 2. 修正案の全体

3 つの柱。A が根本（人の指摘の 1 点目）、B が帯の外の勾配（2 点目）、C は B を安全に成り立たせるために要る。

### A. 速度の値を 1 本の鎖にする

定義を 3 つに分け、上から下へ「小さくなるだけ」の関係にする。

1. **車体の能力 V_full**（PRM-39）：倒し切りの速度。指令→倒し量の正規化だけに使う。運用の上限ではない。
2. **自律走行の上限 V_auto**（PRM-131 を「自律走行の上限」に改める）：自律走行が出してよい速度の最大。ここから下の値はすべてこれから導く。
   - MPPI の vx_max = V_auto
   - velocity_smoother の前進の上限（PRM-66）= V_auto（今は 1.25 で、MPPI より緩い。独立の値をやめて導出値にする）
   - 区間の制限の既定値 = V_auto（PRM-39 を使うのをやめる）
   - 速度マスクの最大の値 = V_auto
3. **区間の制限**：V_auto 以下の「減速」だけ。V_auto より大きい値は保存時に拒み（monitor の waypoint タブ）、自律走行の開始時の検査でも拒む。
   - 既存の経路の制限（1.25）は、読み込み時に V_auto で頭打ちにし、記録に「区間 n：1.25 → 0.5」と残す（移行の措置）。

これで速度制限の比率は常に 1 以下になり、(b) の引き上げは起きない。

検査ルール（追加、承認事項）：
- DR-新1：PRM-66 は PRM-131 と同じ値（導出）。
- DR-新2：区間の制限はすべて PRM-131 以下。
- DR-新3：PRM-131 ≤ PRM-39。

### B. 速度マスクの帯の外に勾配を付け、「制限なし」をなくす

帯の中心線からの距離 d に応じて、マスクの値を次のようにする。

| 距離 d | 値 |
|---|---|
| d ≤ W_band（PRM-19、1.0 m） | 区間の制限（≤ V_auto） |
| W_band < d ≤ W_band + L_ramp | 区間の制限から V_slow へ直線で下げる |
| それより外、帯のない所すべて | V_slow |

- 新しい値（承認事項、値は推奨）：L_ramp（勾配の長さ）2.0 m、V_slow（帯の外の速度）0.3 m/s。
- マスクの 0（制限なし）は使わない。刻み PRM-20（0.05 m/s）なので、勾配は 0.05 m/s 刻みで表せる。
- 帯が重なる所は今までどおり低い方（DEC-045）。
- 効果：スタートから最初の waypoint までの区間、避けて帯から外れた所、コースの外側で、速度が急に変わらず、遠ざかるほど遅くなる。角の手前で「制限なし → 制限」の切り替えも消える。
- 変える決定：DEC-045・DEC-055（帯の外は制限なし、境界の扱いは未設計）を置き換える。
- 「適用中」の判定（DEC-047・DEC-056、`speed_limit_state`）：今は「帯のセル（>0）にいて、正の制限を受けた」で適用中。0 のセルがなくなるので「帯の外」の状態が出なくなる。判定は「マスクの中にいて、正の制限を受けた」に読み替える（意味は変わらない。帯の外にいれば V_slow が適用中）。承認事項。

**注意（C が要る理由）**：V_slow を 0.3 にすると、MPPI の中の下限 0.27 も比率 0.3 ÷ 0.5 = 0.6 で 0.16 m/s に下がる。0.16 m/s の指令は不感帯（前進の倒し量 0.21 で動く。DEC-445）より下なので、車体が動かない。つまり B を MPPI の中の下限と組み合わせると、帯の外で止まる。

### C. 下限を MPPI から外し、車体側（ND-11）で持つ

- MPPI の vx_min（PRM-162）を 0 に戻す。MPPI は「止まる」「その場で向きを変える」を出せるようになる。
- 不感帯の下限は gouda_motion_controller（ND-11）で持つ：目標の速度 v に対して
  - v = 0 → 中立
  - 0 < v < V_move/2 → 中立（止まる方に寄せる）
  - V_move/2 ≤ v < V_move → 動き出す倒し量（V_move＝実測の最低速度 0.09 m/s、DEC-445）
  - v ≥ V_move → 実測の倒し量→速度の表で変換（REV-241 のフィードフォワード）
  - 行き来を防ぐヒステリシス（承認事項、値は推奨：0.02 m/s）
- 旋回も同じ扱い（その場の旋回の倒し量は実測 左 0.30・右 0.18、第192便）。
- DEC-480（下限 0.27 を MPPI に入れる）の見直しになる。承認事項。
- 期待する効果：角で曲がれないときに止まれる。植込みの真横で前に出ずに向きを変えられる（第251便の仕組み B の対策）。コーンの手前で止まれる（ただし止まったままでは滞留になるので、避ける処理と組）。
- 発進できない問題（#61）は、open_loop（PRM-141）と ND-11 の下限で担う。模擬で確かめる。

## 3. 併せて確かめる値

- PRM-73（角加速度 0.5 rad/s²）と PRM-67／132（0.5 rad/s）：0.5 rad/s に達するまで 1 秒かかり、角を曲がる余裕を減らす。意図した値か確認（元は 2.0 rad/s²）。
- 勾配で速度制限が下がると wz_max も比率で下がる（上流の仕様）。V_slow 0.3 のとき 0.3 rad/s。遅い所で旋回も遅くなるのは許容か確認。

## 5. 先行事例

- Nav2 の SpeedFilter：絶対値のマスク（type 2）はセル値 1〜100 × 刻みなので、勾配はマスクの値だけで表せる。Nav2 本体は変えない（RQ-I056）。
- MPPI の速度制限で vx_min・wz_max も比率で変わるのは上流の仕様（別のセッションの読み）。制限を「遅くする方向にだけ使う」決まりは、呼ぶ側で守る。上流の issue での議論：未調査。
- KUAMS（TC2025 完走）の速度の扱い：design/research/kuams_tc2025_2026-10-23/ に速度マスクの勾配の記述はない（第238便の調べ）。

## 6. 残るリスク

- V_slow・L_ramp・ヒステリシスの値は推奨値で、実測の裏付けがない。
- C で MPPI が止まれるようになると、障害物の前で止まったままになる場面が増えうる（滞留 3 分）。waypoint を飛ばす処理（DEC-367）と goal の出し直し（DEC-460）との組で確かめる。
- B で帯の外が遅くなると、避ける動作が遅くなる。歩行者の場面で確かめる。
- 今の経路のデータ（区間の制限 1.25）は、A の移行の措置で 0.5 に頭打ちになる。意図して速い区間を作る場合は、V_auto を上げる。
