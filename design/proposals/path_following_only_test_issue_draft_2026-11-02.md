# 回避オフで経路追従のみの試験（案）

状態：提案。未承認で、実装していない。効果と順番は AI の案で、実車では未確認。

## 目的

回避と追従のどちらが悪いのかを切り分ける。回避の試験の代わりにはならない。

## 分かること

- 追従の実力：経路からのずれ、揺れ、実際に出せる速度
- 自己位置：走り続けたときの NDT・GLIM の遅れ、推定不能の出方
- 車体の応答：指令と実速度のずれ、停止距離（DEC-378）

## 構成の案

RPP で行う。MPPI が既定になったので（REV-190、未コミット）、どちらの案でも `controller_use_mppi` を false にする。

- 案 A：/config で PRM-114（RPP の衝突検査）と PRM-122（コストによる減速）をオフ。コード変更なし。global costmap の印で経路は曲がるので、純粋な追従試験にならない
- 案 B（AI の推奨）：A に加えて global costmap の障害物層もオフ。local の障害物層は残し、走行に影響させずに RViz・rosbag で印を観察する。global の層のオン・オフを /config に足す小さな実装が要る。既定はオンのまま

## 順番の案

1. 経路追従のみ（案 B）。0.5 m/s から順に 1.25 m/s まで
2. RPP の衝突検査をオン（global は切ったまま）。誤って止まらないかを見る
3. global の障害物層もオン（通常の RPP の構成）。置いたコーンを避けられるか
4. 既定の MPPI の構成で同じコースを走って比べる（design/proposals/mppi_trial_2026-11-02.md）

## 安全

- 自動では何も止まらない。collision_monitor もないので、経路上の人や物にそのまま向かう
- 人が入らないよう区切った場所で、すぐ手動で操作できる人を付ける。PC 出力の中立は停止の保証にならない
- 停止距離は未測定（DEC-378、Q-06）。分かるまでは周囲の余裕を大きく取る
- RPP は経路をなぞるだけなので、大きくずれたときの keepout の歯止めにならない
- 通常設定への戻し忘れを防ぐため、起動時に状態を記録に残す

## 前提

- /config の該当項目は第165便以降。実車の PC への反映が要る
- range_max の修正（f61a71b）は main に入っていない。印を観察するなら先に入れる
- 走行中に rosbag を取る（points、scan、/tf、/tf_static、local・global costmap、cmd_vel、plan）
