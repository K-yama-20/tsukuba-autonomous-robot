## 1. 目的

帯の地図（案 C）だけでは、帯の外は全部「不明」で、Nav2 は「本当に行ってはいけない所」（車道：TK-14、緑ロードコーンの歩行者側：TK-39、朱色路側帯の外：TK-41、段差の下など）と「行ってもよい所」（広場、広い歩道）を区別できない。人が、帯と 3D 点群を重ねた図の上で、二つの範囲を描く。

- 走行禁止：Nav2 が経路を引かない（通れない格子）。帯の中でも、描けば禁止になる。
- 走行可：帯の外でも、Nav2 が「空き」として扱う（帯がふさがれたときの迂回先）。
- どちらも描かない所：今の決定どおり（帯の中は空き、帯の外は不明＝高い費用で通れる）。

## 2. 確かめた事実（Nav2 jazzy の上流のソース、2026-10-21）

| 事実 | 出典 |
|---|---|
| KeepoutFilter は、マスクの値を費用に変えて costmap に書く。書くのは「マスクの費用が今の費用より大きい」か「今の格子が不明」のときだけ。マスクの不明の格子は飛ばす | keepout_filter.cpp `process`、costmap_filter.cpp `getMaskCost` |
| したがって、マスクの「空き」は、不明の格子を空きに変える（走行可に使える）。マスクの「占有」は通れない格子にする（走行禁止に使える）。通れない格子（実際に見えた障害物）を空きにはできない | 同上 |
| filter info の type は keepout が 0、速度（m/s）が 2。keepout は base 0・multiplier 1 でなければエラーを出す | filter_values.hpp、keepout_filter.cpp |
| filter の plugin は filter_info_topic（必須）・transform_tolerance・enabled を持つ。マスクの topic は info の中で渡す。一つの info server は一つの info を出すので、速度と keepout で server を二組置く | costmap_filter.cpp、costmap_filter_info_server.cpp |
| KeepoutFilter に、global・local の制限はない（rolling かを見ていない） | keepout_filter.cpp、costmap_filter.cpp |
| override_lethal_cost（既定 false）を true にすると、ロボットが禁止の範囲の中にいるとき、そこから出るための費用に下げる | keepout_filter.cpp `initializeFilter`・`process` |

## 3. 描く場所と保存の仕方

### 3.1 推奨：waypoint セットと一緒に保存する（今の速度マスクと同じ流れ）

- monitor の waypoint タブの地図（帯と 3D 点群の重ね図。§4）の上に、多角形で「走行禁止」「走行可」を描く。waypoint と一緒に保存する。
- 保存のとき、速度マスク（speed_filter_mask）と同じ格子で keepout のマスク（keepout_filter_mask.yaml・.pgm、filter info の yaml）を作る。禁止は占有（100）、走行可は空き（0）、どちらでもない所は不明（-1）。
- waypoint セットの内容ハッシュに範囲も入る（RQ-I078 の同一性はそのまま）。自律走行の開始（TR-05）で、速度マスクと同じく keepout のマスクを Nav2 に読み込ませる。
- 理由：速度マスクの仕組み（保存、ハッシュ、TR-05 での読み込み、適用状態の確認）をそのまま使える。新しいデータベースや地図の作り直しが要らない。
- 不便な点：同じ地図で waypoint セットを作り直すと、範囲も描き直しになる。前のセットの範囲を写す操作を用意する（案）。

### 3.2 代わり：地図（変換の rev）に付ける

- 範囲は「場所」の性質なので、地図に付ける方が意味は素直。描いたら再変換して新しい rev にする。
- 不便な点：範囲を直すたびに地図の rev が変わり、その地図を参照する waypoint セットを全部作り直すことになる（地図の版とハッシュを持つため）。

## 5. Nav2 の設定

- global costmap と local costmap の両方に KeepoutFilter を置く（local にも置くのは、後退・回転の回復（behavior_server）と追従（RPP）が local costmap で衝突を判断するため）。
- server を二組にする：今の速度の filter_mask_server・costmap_filter_info_server（type 2）と、keepout 用の二つ（type 0、base 0、multiplier 1）。
- override_lethal_cost は false のまま（推奨）。禁止の範囲の中に入ったら、自分から出ようとしない。代わり：true にして、外へ出る経路を許す。
- 禁止の範囲の縁の扱い：§2 の未確認 1 が推測どおりなら、保存のときに禁止の範囲を車体の半分の幅（PRM-02 の半分、0.30 m）だけ広げてマスクに書く（推奨。人が描いた線から車体がはみ出さない）。広げる幅は設定（PRM、値は人が決める）。

## 9. 残るリスク

- 人が描かなかった所は、今の決定どおり帯の外は「不明＝高い費用で通れる」。描き忘れた車道は、帯がふさがれたときに経路に入りうる。
- 禁止の範囲は Nav2 の経路と追従の判断にだけ効く。車体の停止の保証ではない（CLAUDE.md 1.5）。自己位置がずれれば、禁止の範囲も実際の場所からずれる。
- 描いた範囲と、実際のコースの変化（工事・駐車）は合わなくなりうる。
