## 1. 目的と範囲

- 目的: 最初の自律走行に要る Nav2 の 2D 地図（変換の map.yaml）を、床の反射・2 層の地面・地図の傾き（G-FLOOR-REFLECTION、G-LIDAR-DROPOUT、G-MAP-TILT）に影響されずに作る。
- 考え方: 経路は地図作成で通った道の上に置く（intent.md 7〜9 行の流れ）。そこで、地図作成のときに車体が通った位置の近くだけを「空き」にし、それ以外は「不明」にする。地面を推定しないので、点の高さは 2D 地図に使わない。
- 範囲: 変換（ND-05、map_convert）の 2D 地図の作り方、Nav2 の設定の 1 か所（§5）、waypoint の保存の確認（§6）、試験。自己位置推定（ND-07、案 A3）は 3D の点の格子をそのまま使うので、この提案とは独立している。

## 3. 2D 地図の作り方

### 3.1 入力

- 原図の `traj_imu.txt`（IMU の姿勢の列、補正後）。
- base_link から IMU までの取付（/config の imu_mount_*）。原図の横の /config の写しを使う。写しがない古い原図は、変換のときの /config を使い、そのことを manifest に記録する（§9 の 3）。/config が UNKNOWN の項目は中立（0）で計算し、記録する（RQ-I081 と同じ扱い。GLIM の T_lidar_imu と同じ）。
- 新しい設定（§4）。

### 3.2 手順

1. 軌跡の各姿勢から base_link の水平の位置と向きを求める（T_map_base = T_map_imu・T_imu_base。z と傾きは使わない）。
2. 隣り合う姿勢の水平の距離が「つながないとみなす距離」（§4 の B）を超えたら、その間は線でつながない（LiDAR の途切れで跳んだ所を空きにしない）。
3. つながった区間ごとに、base_link の通り道（折れ線）から「帯の半分の幅」（§4 の A）以内の格子を空き（254）にする。
4. それ以外の格子は不明（205）。占有（0）の格子は作らない。障害物は走行中の LiDAR で Nav2 の costmap が扱う（ND-09、DEC-122 の案 a）。
5. 格子の大きさ・原点は今の 2D 地図と同じ決め方（PRM-33 の解像度。範囲は帯の外接の長方形に余白 1 格子）。

| `map_ground_band.yaml` + `.pgm`（新しい名前） | — | 今の分類の 2D 地図。表示と比べるためだけ（走行には使わない）。地図タブで帯の地図と並べて見る |

- 変換器の版を上げる。同じ原図からの別の rev になる（intent.md:7。前の rev は残る）。
- 軌跡がない・読めない原図は、2D 地図を作らずに変換を失敗にし、理由を残す（今の分類の地図に黙って戻さない。原図は保持される：RQ-I009）。

## 4. 新しい設定（PRM。値は未確定。人の承認が要る）

| | 設定 | 意味 | 値の候補と振る舞いの違い（推奨は置かない。人が決める） |
|---|---|---|---|
| A | 帯の半分の幅 | base_link の通り道からこの距離以内を空きにする | 0.3 m: 地図作成の通り道からほとんど外れない（迂回はほぼできない）。0.5 m: 人の通り道から片側 0.5 m まで。1.0 m: 歩道の幅によっては車道側・植え込み側の不明な所に掛かる（歩道の幅の実測がない） |
| B | つながないとみなす距離 | 隣り合う軌跡の点の間がこれを超えたら線でつながない | 軌跡は約 10 Hz（GLIM の処理周期、FILE-EVENING-MAPS-ROSBAG）。歩く速さ（約 1 m/s）では 1 周期で約 0.1 m。途切れのとき 2.7〜12.6 m 跳んだ。この間の値（例 1 m）なら、通常の点はつながり、途切れはつながない |

- 今の分類の設定（PRM-34〜36・38・62〜64、DEC-098 で承認）は、表示用の `map_ground_band` にだけ使う。走行に使う 2D 地図には使わなくなる（役割の変更なので承認事項：§9 の 2）。
- 地図タブの入力欄に A・B を足し、再変換で試せるようにする（intent.md:106）。

## 5. Nav2 の設定（1 か所）

- 経路の計画（NavFn）の `allow_unknown` を false にする（今は上流の既定の true）。不明な所を通る経路を作らない。intent.md:15「観測外を安全とみなさない」に沿う。
- 振る舞いの違い: true のままだと、帯の外の不明な所（地図作成で見ていない所）にも経路を引きうる。false では、帯の中（と、下の「未確認」の点で開く所）だけに経路を引く。経路が引けないときは BT の recovery を経て、PRM-18 の回数の後に TR-07（計画の失敗）で一時停止する。
- **未確認（実装の最初の試験で確かめる）**:
  1. global costmap の obstacle_layer は clearing が true なので、走行中に LiDAR の光線が通った所は、static_layer の「不明」が「空き」に上書きされる見込み（costmap の層の合成は既定で「大きい方を取る」で、不明は上書きされる側：AI の推測。上流のソースで確かめていない）。そうなると、走行中に見えている所へは帯の外でも迂回できる。
  2. ただし、光線が通っただけの所（側溝・段差の下の地面など、高さの帯 PRM-70・71 で障害物にならない所）も空きになる。負の障害物（溝）は検出していない（この設計の外。CLAUDE.md 1.5：中立化は停止の保証ではない）。
  3. 1 の推測が正しい場合の選択肢: (a) そのまま（見えた所への迂回を許す）、(b) static_layer を obstacle_layer の後に置く・合成の方法を変えるなどで、帯の外を開かない。どちらにするかは、VM での確認の結果とともに改めて示す。

## 6. waypoint の保存の確認

- waypoint の保存（monitor の waypoint タブ、waypoints.py）で、各 waypoint が帯の地図の空きの格子にあるかを確かめる。外にあれば保存を拒否し、どの点が何 m 外かを返す（案）。代わり: 警告だけにして保存する。
- 理由: allow_unknown が false では、帯の外の waypoint へは経路が引けず、走り出してから計画の失敗になる。保存のときに分かる方が人に分かりやすい。
- waypoint のプレビューは帯の地図（白い帯と灰色の不明）になる。周りの様子は高さの図・`map_ground_band` を重ねて見る（表示の変更は小さい：地図タブの切り替え）。

## 7. 失敗モードと扱い

| 失敗 | 扱い |
|---|---|
| 軌跡のファイルがない・空・読めない | 変換を失敗にする（理由を表示）。原図は保持 |
| /config の写しがない（古い原図） | 変換のときの /config を使い、manifest に記録（§9 の 3 で人が決める） |
| 取付が UNKNOWN | 中立（0）で計算し記録。IMU が base_link から水平に離れている分だけ帯がずれる（ずれの大きさは記録した取付で分かる） |
| LiDAR の途切れで軌跡が跳んだ | B の距離でつながない。跳んだ前後で地図自体がずれている場合（G-LIDAR-DROPOUT）は、帯もずれる。3D の照合（A3）もずれた地図に合わせるので、帯と自己位置は同じ地図の上ではそろう（推測）。ずれた地図は地図作成のやり直しが要る |
| 地図作成で人が押した・止まった所 | 帯の外へ出ない。停止した所は空きの点が重なるだけ |
| 帯が狭すぎて曲がれない（角の内側） | 経路が引けず、TR-07（計画の失敗）。帯の幅 A を広げて再変換 |
| 地図作成の経路と違う道を走りたい | できない（地図作成をやり直す）。案 C の制約 |

## 8. 試験

- 単体（test_mapping_core.py）: 合成の軌跡（直線・曲がり角・跳び）で、空きの格子が通り道から A 以内にだけあること、跳びをつながないこと、取付のずれ（IMU が前に 0.3 m など）が帯の位置に反映されること、軌跡がない原図で変換が失敗すること。設計に反した写し（例: 跳びをつなぐ）で試験が不合格になることも確かめる。
- 実データ（分析用の再変換。地図データベースには登録しない）: VM の 2 回目の廊下、x86 機の廊下・屋外の原図。帯の地図と `map_ground_band` を並べて人に示す。
- VM の Nav2（試験の基盤、loopback_sim）: 帯の地図で、帯の中の waypoint に着くこと、帯の外の waypoint では経路が引けず TR-07 になること、§5 の未確認の 1（見えた所が開くか）。
- 実車: 最初の自律走行（人の判断）。

## 10. 残るリスク

- 帯の外へ迂回できないことがある（§5 の未確認の 1 による）。歩行者などで道がふさがると一時停止する（DEC-200 の「失敗が外から見て明らか」に合うが、本番の走行では止まる回数が増えうる）。
- 2D 地図に障害物がないので、遠くの壁・段差は経路の計画に入らない。帯の中に入る障害物は、走行中の LiDAR で見えたものだけ。見えない溝・段差の下は扱わない。
- 地図作成のときの軌跡の誤り（途切れのずれ）は、そのまま帯の誤りになる。
- 案 A（地面の推定）で解こうとしていた「縁石・側溝・坂を地図に入れる」ことは、この案では解かない。DEC-105 の後に案 A を再検討する。
