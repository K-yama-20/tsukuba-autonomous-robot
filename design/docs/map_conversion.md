# 地図の変換（原図から各種の地図へ）と地図作成の実機試験（DEC-092〜DEC-100、REV-039〜042）

状態: 正本（Markdown）。案（design_status 案）。人の回答 DEC-093・DEC-095・DEC-096・DEC-097 による。モデル: ND-05（gouda_map_creator）、ND-02（gouda_monitor の地図タブ）、IFD-29（地図データベース）、IFD-37（map/convert）、PRM-33〜36・38・62〜64、TS-27・TS-33・TS-34、DEC-098（暫定の推奨値の承認）、DEC-099・DEC-100（実測）。

## 1. 1 回の変換で作るもの

変換は原図（GLIM の dump）から次をまとめて作り、変換後地図の 1 つの rev として地図データベースに保存する（RQ-I008・RQ-I009）。原図は変えない。

| ファイル | 内容 | 使い道 |
|---|---|---|
| map.yaml・map.pgm | 2D 占有格子（Nav2 map_server 形式） | 走行（Nav2）。走行に使うのはこれだけ |
| pointmap.pcd | 3D 点群地図（map 座標、x y z の float32、binary PCD。ヘッダの版は PCD の仕様の例と同じ「.7」）。全 submap の点 | 自己位置推定（DEC-095）。形式は推定方式（Q-02）が決まったら合わせる |
| slope.png・step.png・terrain.json | 地面の傾きと段差（地面を推定する格子ごと） | 人が地図タブで見る確認用。走行には使わない（DEC-097 A） |
| height.png | セルごとの地面からの最も高い点（3D 点群地図を上から見た図） | 人が地図タブで見る確認用 |
| manifest.json | 由来 ID、内容ハッシュ、変換器の版、設定、統計、ファイルの一覧 | 識別と記録 |

## 2. 高さの基準は地面（DEC-093）

GLIM の地図座標は、開始時のセンサーの位置が原点で、地面は z=0 にない（10/13 の原図で点の z は −1.16〜3.74 m）。坂では場所ごとに地面の高さが変わる。そこで、点群から地面の高さを場所ごとに推定し、帯（PRM-34〜36）は地面からの高さで決める。

推定の手順（`gouda_core/gouda_core/map_convert.py` の `estimate_ground`）:

1. 水平の格子（大きさ PRM-62）を作り、格子ごとに最も低い点を取る。
2. 地面の高さは、最も低い点の「傾きを制限した下側の包絡」とする。どの格子の地面も、その格子の最も低い点より上にならず、隣の格子の地面より「傾きの上限（PRM-63）× 距離」以上は高くならない。車体の側面や壁しか見えていない格子では、最も低い点が地面より高いが、隣の地面から決まるので地面が持ち上がらない。
3. 点のない格子は、点のある格子から PRM-64 以内に限って同じ包絡で地面を補う。それより遠い所は地面が不明で、そこの点は分類しない（統計の「地面が不明」）。
4. 点ごとの地面の高さは、格子の中心の値を双線形に補間する。

分類: 地面からの高さが PRM-34 以下の点は地面（そのセルを空きにする）、PRM-35 以上 PRM-36 以下の点は障害物。障害物の点が PRM-38 以上あるセルを占有にする（占有が空きに優先）。地面の点も障害物の点もないセルは未知。

設定の性質（調整の手がかり）:

- 傾きの上限（PRM-63）を大きくすると、急な坂も地面になるが、縁石の上面や低い台も地面に吸収されやすくなる。小さくすると縁石は地面から外れやすくなるが、上限より急な坂の上の方が「地面より高い」と判定され、障害物や帯の間になる。
- 地面の格子（PRM-62）を小さくすると、段差に近い所まで正しく追えるが、点のない格子が増える。GLIM の原図の点の間隔（submap ごとに 0.3 m の格子で間引かれる）より小さくすると穴が増える。
- 地面の帯（PRM-34）は、坂で格子の中の高さが変わる分（格子の半分の長さ × 傾き）と、点の誤差を含む必要がある。
- 地面を補う距離（PRM-64）を大きくすると、車の下や見えない所も地面として扱うが、本当は地面がない所（溝など）も補ってしまう。0 にすると補わない。

## 3. 表示用の地図（DEC-097 A）

- 傾き（slope.png）: 地面とみなした格子（最も低い点が包絡から PRM-34 以内）の最も低い点の高さから、隣の格子との差で求めた傾き。色の目盛りの上限は PRM-63。
- 段差（step.png）: 上下左右の格子との地面の高さの差の最大。坂では 1 格子分の上りを含む。色の目盛りの上限は PRM-35（障害物の下限の高さの段差）。
- 高さ（height.png）: 2D 地図のセルごとの、地面からの最も高い点（PRM-36 まで）。地面だけのセルは濃い緑。
- 色: 緑（0）→ 黄 → 赤（目盛りの上限）、紫は上限を超える、灰はデータなし。
- 走行（Nav2）には使わない。走行に使うかは実機検証の後に人が決める。DEC-097 は「条件付き承認」で、条件の内容は確認中。

## 4. 点の密度（DEC-094 B → DEC-096 C）

GLIM 1.2.2（CPU の設定）で保存される submap の点は 3 段で間引かれる（上流のソース sub_mapping.cpp 254・385・423・496 行、cloud_preprocessor.cpp 105〜106 行）。

1. frame ごとに約 1 万点に間引く（random_downsample_target 10000。XT-32 は 1 frame 64000 点）。
2. submap には keyframe（直前の keyframe との重なりが 0.6 を下回ったときに作る）の点だけが入る。keyframe が 15 個たまると submap にする。
3. keyframe を結合するときに 0.3 m の格子で間引く（submap_downsample_resolution）。

DEC-096 の回答（C 案）により、今は GLIM の設定を変えない。移動して作った原図で密度を測ってから決める（DEC-100）。これまでの原図はすべて静止して作られていた（`research/vehicle_pc/2026-10-14_source_maps_survey.txt`）。

## 5. 地図作成の実機試験（TS-34。DEC-099・DEC-100 の計測）

目的: 移動して原図を作り、(a) XT-32 で地面が映るか、どこが映らないか（DEC-099）、(b) 原図の点の密度と GLIM が処理した周期（DEC-100、G-DDS）、(c) 変換の設定の当たり（DEC-098 の暫定値の見直しの材料）を記録する。

準備:

1. Mac をスリープさせない（スリープすると VM が止まり、USB-LAN が外れ、時計がずれる）。
2. VM に LiDAR の USB-LAN と IMU を接続する。gouda.sh を起動し直した場合、IMU は USB を抜き差しする（supervisor が作り直す）。
3. `bash gouda.sh start`。monitor（http://127.0.0.1:8080/）の運用タブの SENSORS 表で、点群と IMU が RECEIVED であることを確かめる。
4. /config の取付位置（人が設定。RQ-I081）。

手順:

1. 地図作成開始。
2. 車体を手で押すか手動操作で、歩く速さで動かす。経路は 50〜100 m 程度で、平らな所、坂、縁石、壁、木、駐車中の物を含め、できれば出発点に戻る（GLIM のループの閉じ）。経路と途中の物を記録する（写真・メモ）。
3. 地図作成終了。原図が登録され、自動変換が走る（暫定値が未設定なら失敗するが、原図は残る）。
4. 地図タブで原図を選び、設定を入れて再変換する。設定を変えて何度か試し、2D 地図・高さ・傾き・段差を見る。

記録すること:

- 開始・終了の時刻、monitor の SENSORS 表（点群の受信周期）。
- 解析（VM で実行。数値は試験の人が決めて引数で渡す）:
  `python3 -m gouda_core.map_inspect ~/gouda_ws/gouda_data/maps/<origin_id>/source --cell <m> --radii <m> <m> ... --band <m>`
  - GLIM が処理した周期（traj_lidar.txt の行数と時刻。XT-32 は 10 Hz）と最長の欠け。
  - 経路の長さ、submap の数、点の数、経路から各距離以内の点の密度（点/m²）。
  - 経路から各距離以内の格子のうち点がある割合と、低い点（周りの最も低い点から --band 以内）がある割合。経路のすぐ近くは XT-32 の死角になりうる。
- 変換の統計（地図タブの表）: セルの占有・空き・未知、点の分類（地面・障害物・帯の間・上限より上・地面が不明）、地面の格子（点あり・地面・補った）、傾きと段差の最大。
- 地図タブの各図の画面。

記録の置き場: `design/research/vehicle_pc/<日付>_mapping_field_test.txt`（解析の出力と条件）。人の判断（暫定値の再指定など）は判断台帳に原文で残す。
