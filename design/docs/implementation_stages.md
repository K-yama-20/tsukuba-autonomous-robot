## 3. 試験不合格時の扱い（DEC-056、CLAUDE.md 1.6）

- 観測事実（ログ・実行 ID・コミット ID・条件）と根本原因を作業記録に書く。原因を仕様／設計／実装／設定／試験／物理特性に分類し、その層で直す。
- 設計の欠陥なら、変更セット（REV）→ 再生成（render_views・generate_params）→ 検査（run_checks）を経てから実装に反映する。
- 根拠のない timeout の拡大、retry の追加、例外の握りつぶし、期待結果の変更は行わない。期待値を変える場合は根拠を示し人の承認を得る。

## 4. 本工程で参照するが確定ではないもの

- 承認済みの値: PRM-07・PRM-08・PRM-13・PRM-21 のみ。その他の実車値は未確定（Q-04〜Q-06）。仮値は `software_trial_value`（根拠付き）で、実車に流用しない。
- DEC-050（配線・firmware・操作結果の実機照合）と Q-04〜Q-06 は、承認済み・実測済みとして扱わない（DEC-053）。
- GLIM の版（IFD-35）、新 firmware の版（G-FIRMWARE）は未固定。
