## 3. 守ること（このチャットで増えた注意）

- commit メッセージと PR の説明に「Co-Authored-By: Claude …」「Generated with Claude Code」の行を入れない（人の決まり。アプリの指示より優先）。過去の commit は書き換えない。commit の前に `git log -1 --format='%an <%ae> | %cn <%ce>'` で、作者が人の git の設定（aaa111aaa-111a）であることを確かめる。
- main への merge は、Claude Code の権限の仕組みに止められる。回り込まず、人が GitHub の画面で行う（または人が許可を設定する）。
- この作業コピーの fetch の設定は feat/architecture（リモートに無い）だけを取る。設定は変えず、`git fetch origin '+refs/heads/main:refs/remotes/origin/main'` のように名前を指定して取る。
- 分岐セッションの判断材料と人の回答が「転記」として貼られることがある。人が貼ったことを着手の指示とし（それまで変えない、という人の指示があった）、台帳には「転記」と書く。
- 変更セットは Python（ruamel.yaml）で組み立てて書き出すと、ASCII のコロンを含む文の引用の誤りを避けられる。pending の DEC は answer_verbatim ''、disposition open_human。
- source_value の PRM の値を変えるときは、出典（source_refs）を新しい版の行に付け替える（DR-11 は出典の文に数字があるかを見る）。
- `--dry-run --check` の「新しい未判定」は、既存の行の見出しの文が変わっただけのことがある（同じ数の承認値が増えたとき、DR-15）。中身を見て判断する。
- intent.md の人の編集に、不自然な値（例：全高 120 mm が後輪径 330 mm より小さい）があれば、推測で読まずに人に確かめる。
- 試験の期待値を変えるときは、承認された仕様の変更（DEC）を根拠にする。試験の基盤だけを直すときも、合否の基準は変えない（第93便）。試験を足したら、規則を壊した写しで不合格になることを確かめる。
- 以前の注意（handover_2026-10-21.md §3）もそのまま有効：VM への写しは `~/gouda_unit_tree` や作業用のワークスペース（第86便は `~/gouda_rev118_ws`）に。ROS の結合の試験は ROS_DOMAIN_ID 77〜79。VM で動いている Gouda（`~/gouda_ws`）を止めない。自分で起こしたプロセスだけを PID で止める。
