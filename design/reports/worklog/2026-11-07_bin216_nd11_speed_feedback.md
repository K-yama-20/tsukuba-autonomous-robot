## 自律判断（理由）

- /config の項目は、同じタブ・同じファイル・同じ message（IFD-52）に足した。monitor と ND-11 の配線を一つにするため。
- 層が有効の間は、第86便の補償を使わない。フィードフォワードに不感帯が入っているので、二重にしない（指示）。
- 積分を止める条件：倒し量の合計（フィードフォワード＋P＋I）が、誤差の向きに 1 を超えるとき、または 0 を下回るとき（control_toolbox の条件付き積分と同じ考え方）。
- PI は倒し量を目標の反対の向きにしない（減らすのは中立まで）。目標の符号が変わったら、その軸の積分を 0 にする（DEC-451 (5)(6)）。
- 手動の優先は、IFD-38 の source が manual かで判断する（DEC-453）。
- 番号：PRM は 150〜160、IFD は 70。他の作業との重なりを避けるため、間を空けた。

## 模擬の比較（実行したものだけ）

詳細と全部の表は `research/vehicle_pc/2026-11-07_ffpi_sim/README.md`（`results_r1.md`）。

- 車体モデル：別のセッションの写しの m1107（DEC-445 の不感帯・最低速度・旋回の不感帯、旋回の立ち上がり約 2.4 s、止まった状態からの遅れ 0.6 s）。足したものはない。前進の傾き・前後の時定数・指令の遅れ・後退は仮の値。
- 走らせたもの：層なし／層あり（旋回も PI の on と、旋回は FF だけの onv）× MPPI（open_loop true・false）／RPP × 障害物なし・遅れて出るコーン。層ありは GLIM の速度の遅れ 0.1 s・0.3 s。各条件 1〜2 本。

| 比べた点 | 層なし | 層あり（遅れ 0.1） |
|---|---|---|
| MPPI open_loop true の発進と速度（障害物なし） | 1.3 s で発進、0.40 m/s、速度の差 0.20 | 0.7 s、0.60 m/s、速度の差 0.01。横ずれは悪くならない |
| MPPI open_loop false（障害物なし） | 0/2（動かない） | 4/4 ゴール |
| 旋回の揺れ（走行中の sd） | 0.02 rad/s | on 0.15、onv 0.055 |
| 遅れ 0.3 s | — | open_loop true・RPP は 0.1 と同等。open_loop false は動く・止まるの繰り返しでゴールできない |
| 遅れて出るコーン | open_loop true は接触 0/2（0.19〜0.38 m/s） | 9 本すべて接触（間隔 −0.04〜−0.15） |

- Python の探索：目標 0.04 m/s（最低速度より遅い）では、動く・止まるを繰り返した（懸念 2 を模擬で確認）。積分の上限 0.3 は、始動の遅れの間に積分がたまり、最大 +0.34 m/s 行き過ぎた。

## 既知の懸念（調べた結果。判断は人）

1. GLIM の速度の遅れ：IFD-25 は (B) より約 50 ms 遅い。配信の遅れは未測定。遅れが大きいと PI が振動する。模擬で 0.1 s・0.3 s を見ている（実行中）。
2. 最低速度より遅い目標：フィードフォワードは不感帯の中の倒し量になる。積分で動き出すと 0.09 m/s で走り、目標より速いので積分が減って止まる。これを繰り返すおそれがある（DEC-451 (4)、未確認）。
3. 推定不能の間：層は localization/status を見ていない。GLIM そのものが崩れると、誤った速度で直す。ND-07 の推定不能（第196・198便）と GLIM の odometry の故障は別だが、見分けていない。
4. 実測は各条件 1 回で、床の傾きを分けていない。倒し量 1 の速度は実測していない。
5. その場の旋回の表がない：前進しながらの表を使っている。左右で 1.7 倍違う（#66）。差は PI に頼る。
