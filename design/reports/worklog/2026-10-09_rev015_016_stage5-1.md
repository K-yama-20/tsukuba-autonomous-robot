## 3. 自律判断と修正の分類（1.6）

- 実装（検査器）: DR-15 のハードコード走査が承認値 1.0 を `%g` の「1」で探していたため、列挙コードや添字の「1」をすべて未判定にする。float のリテラル形（`1.0`・`1.`・`0.7`・`0.25`）だけを探すよう精度を上げた（検出範囲を広げも緩めもしていない。試験 2 件を追加）。
- 実装（生成器）: 値の宣言がない node の生成パラメータファイルが `ros__parameters:` だけ（YAML では null）になり ROS 2 のパラメータファイルとして不正になり得たため、`ros__parameters: {}` を出すようにした。launch 側でも値のないファイルは渡さない。
- 試験基盤: 書込失敗の試験でディレクトリの権限変更では追記を止められなかったため、既存ファイルを読み取り専用にする方式に直した。合否の基準は不変。
- 設計: PRM-25（データルート）は実車値ではなく運用値。unresolved とし G-LOG で追跡、作業値は旧実装の記録先の慣例に倣う（実車採用値ではない）。
- ROS 2 実行環境がこの作業機にないため、ビルド（colcon）・launch・サービス呼出しの確認は未実施。実車PC での確認手順を §5 に書く。

## 5. 実車PC（または ROS 2 Jazzy 環境）での確認手順（人に依頼）

```bash
cd ~/gouda_ws && colcon build --packages-select gouda_interfaces gouda_core && source install/setup.bash
cd ~/gouda_ws/src/tsukuba-autonomous-robot && python3 -m unittest discover -s gouda_core/test
bash gouda.sh start && sleep 5 && bash gouda.sh status
ros2 topic echo --once mode/state            # mode=1（手動走行）、state_revision=1、initial_pose_required=false
ros2 topic echo --once record/status         # log_active=False, rosbag_active=False（起動時に記録しない）
ros2 service call /record/log/start std_srvs/srv/Trigger && ros2 service call /record/log/stop std_srvs/srv/Trigger
ros2 service call /record/rosbag/start std_srvs/srv/Trigger && sleep 3 && ros2 service call /record/rosbag/stop std_srvs/srv/Trigger
ls -R "${GOUDA_DATA_ROOT:-$HOME/gouda_ws/gouda_data}"/records | head -30
bash gouda.sh stop
```

出力を `design/research/vehicle_pc/` に保存する。再起動で `previous_mode_record.json` が `manual` のとき TR-01、手で `{"mode":"autonomy"}` にして起動すると mode=4（一時停止）・initial_pose_required=true になること（TR-02）も確認する。
