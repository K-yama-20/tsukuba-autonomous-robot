## 4. 今回止まった原因

- 直接（事実）：回復を続けた後、BT が planner に経路を頼んだとき、planner が 20 ms（`default_server_timeout: 20`、上流の既定値）以内に受け付けを返さず、BT が失敗した。error_code は 0
- その前の、前に進めなくなった原因（事実）：12 s の時点から RPP が「collision ahead」を出し続け、前進の出力が 0 になった。回復の backup も「Collision Ahead」で止まった。つまり local costmap の中で、車体の前後に障害物があるとされていた
- 障害物が何で、何 m 先かは記録から分からない（rosbag なし、Nav2 の log は距離を出さない）
- 候補（推測）：第160便 §9 のとおり、障害物の高さの帯が odom の z（原点は IMU の高さ）で当たり、地面から約 1.0〜2.2 m の物を障害物にしている（DEC-336、承認待ち）。そばを歩く・立つ人の胴や頭が、車体の前後 2.5 m 以内に入ると止まる
- planner が 20 ms で受け付けを返さなかった理由は分からない（その時刻の CPU の記録なし）。controller の周期の落ち込みと同じく、一時的な処理の詰まりが考えられる（推測）
