## 4. 前のチャットで分かったこと（次の作業で使う）

- GLIM（1.2.2）を odometry だけで動かす場合（config_ros.json の enable_local_mapping・enable_global_mapping を false）:
  - TF と odometry の topic は librviz_viewer.so が出す。TF は「map_frame_id → odom_frame_id → base」と「imu → lidar」。map→odom は global mapping がない限り単位行列（TrajectoryManager の初期値）。
  - frame の名前を付け替えれば（map_frame_id=odom、odom_frame_id=odom_glim など）、照合器の map→odom と重ならない。publish_imu2lidar は false にできる。
  - `~/odom` の子の frame は IMU で、角速度がない。Nav2 用の odometry には中継が要る。
- lidar_localization_ros2（案 A）: Nav2 用の設定で map→odom を出し、odom→base_link を TF から取る。failure_category は診断だけで、棄却の間は map→odom を最後の値で止める。ソースの build だけ（VM で約 6 分、メモリ 2 本の並列でほぼ一杯）。
- Autoware Core（案 A3。apt の Jazzy 1.9.0）:
  - EKF は map→base_link を出し、止める設定はない。twist の frame_id は base_link 固定。
  - NDT は点群の間引きが前提（0.5 m の格子で score が基準を満たした。1.0 m では score がしきい値を下回る）。地図は pointcloud_map_loader から 20 m 格子（metadata の座標は整数）。
  - 初期化は ndt_align_srv（Monte Carlo）と trigger_node。
- 評価の道具（地図の PCD、odometry の TF の再生、速度の中継、初期化、記録、比較）は `research/vehicle_pc/2026-10-17_localization_eval/tools/` にある。
- Nav2 1.3.13（Jazzy）は VM に入っている（nav2_amcl など）。速度の上限は Nav2 の Speed Filter だけが発行する（DEC-031、`docs/speed_filter_design.md`）。waypoint（工程 5-4）と車体出力（工程 5-5、stub）は実装済み。
