# Gazeboによる実機前の検証

ROS 2 Jazzy / Gazebo Harmonicで、実機用の相対目標コントローラーとESP32の本番制御コアを使って試験します。実機USBは開きません。ROS domainは101、実機は99、設定と記録も別ディレクトリです。未測定の実機取付設定をゼロ埋めすることはありません。

## 起動

初回はUbuntu上のリポジトリで実行します。

```bash
bash scripts/setup.sh --with-glim --with-gazebo --no-configure
```

画面を見ながら試す場合:

```bash
bash scripts/gazebo.sh gui
```

画面なしで自動試験する場合、1つ目の端末で:

```bash
bash scripts/gazebo.sh run
```

2つ目の端末で:

```bash
bash scripts/gazebo.sh scenarios
```

試験には新しく起動した環境を使います。試験終了後は1つ目の端末でCtrl+Cを押し、記録終了を待ちます。毎回新しい保存先 `~/gouda_sim_runs/run-*` が作られ、設定・センサーログ・制御ログを保存します。試験のJSON結果は `/tmp/gouda-gazebo-report.json` です。`GOUDA_BUILD_WORKSPACE` でビルド済みワークスペースを指定できます。

## 試験項目

前進、後進、左右旋回、手動割り込みと復帰、IMU停止、PC通信断、LiDAR停止、リモコン通信断、障害物停止。相対目標を開始時の車体座標から変換し、到達誤差・軌跡・停止理由を保存します。手動割り込みでも目標は保持し、通信異常後は明示的に再開始します。障害物試験では停止時の直方体前端と障害物の隙間も計算します。

## 制御検証とGLIM検証

既定の `estimator:=ground_truth` は、Gazebo物理エンジンの実際のモデル姿勢を位置推定の代わりに使います。車輪オドメトリーではありません。制御の不具合を切り分けるモードで、SLAM成功の証拠にはなりません。

仮想点群・IMUからGLIM自身に推定させる場合:

```bash
bash scripts/gazebo.sh run estimator:=glim
```

別端末で `bash scripts/gazebo.sh scenarios -p suite:=motion` を実行すると、通信故障注入を除く6種類の走行試験になります。

この場合、正解位置は評価・記録用に残し、コントローラーにはGLIMの出力だけを渡します。GLIMの初期化と位置更新を待ってからシナリオを実行します。GLIM実行ログと地図の出力は同じ試験フォルダに保存します。

## 今回の結果

制御を切り分ける正解位置モードでは10ケースが成功しました。GLIMを使うモードは**未合格**です。長い廊下の試験で推定速度・位置がずれて到達せず、試験タイムアウト時に中止しました。最後の比較では推定x約0.189 m、Gazeboの実位置x約0.561 mでした。実機でのGLIM精度を保証する結果ではありません。

この試験で、GLIMの処理遅延と最新IMUの時刻差を単純比較していた問題を修正しました。IMU履歴から位置推定と同時刻のサンプルを選び、並進速度の取付位置補正に使います。旋回フィードバックは最新IMUを使い、両時刻を記録します。無限大だけの点群を有効入力扱いしないようにしたほか、GLIMを含む起動・終了も統一しました。

シミュレーション時間は既定で実時間の0.5倍です。`real_time_factor:=1.0` で等速にできますが、処理負荷による監視停止も試験結果として確認してください。

## モデルの仮定

外形は共有図面に基づく長さ1.105 m・幅0.600 m・高さ0.950 mの直方体です。車輪径・左右間隔・質量・摩擦・取付位置・応答速度は**シミュレーション用の仮定値**です。実機を測定した値ではありません。横移動はなく、前後進と旋回を組み合わせます。

仮想左右駆動ゲインは左0.96、右1.0。左流れを与えています。`left_gain:=1.0` なら左右同一条件になります。応答は時定数0.15秒の一次遅れ、仮想LiDARには標準偏差0.01 mの距離ノイズを加えています。実機の制御ゲインには反映しません。

## LiDARの描画方式

既定の `lidar_backend:=cpu_ray` は、Gazeboから得た実際の姿勢で16×720本の光線と、同じ廊下・障害物形状との交点を計算します。CPU計算の静的環境専用です。自己形状は既知として除外し、実機の障害物フィルターは変更しません。各スキャンは瞬時サンプルのため、点の相対時刻はゼロです。回転型実機LiDARの走査歪みは再現していません。

描画式LiDARも `lidar_backend:=gpu` で選択できますが、このMac上のARM Ubuntu仮想環境では正常な距離画像を取得できていません。試験済みとして扱わないでください。CPU方式は任意の追加・動的モデルを自動では検出しません。環境変更時はCPU交差判定の形状も合わせる必要があります。

## 実機で残る確認

シミュレーションで制御の符号、状態遷移、衝突判定、記録・再現を先に確認できます。実機の取付方向、電圧から実速度への応答、滑り、実際の通信断停止、物理非常停止の確認は置き換えられません。実機に近づける段階では既に記録する指令・センサー値から、仮定の駆動ゲインと応答遅れを調整できます。
