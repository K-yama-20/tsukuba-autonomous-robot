# Gouda 自律走行MVP

現在位置からの相対目標へ、前後移動と旋回で進む実装です。真横への移動指令は出しません。旋回して移動し、最後に指定向きへ合わせます。後方の目標には後進を使います。経路上に障害物がある場合は停止し、障害物がなくなると継続します。迂回経路探索は今回のMVPには含みません。

## 実装と確認範囲

ESP32-DevKitC-VE / ESP32-WROVER-E用ファームウェアは `firmware/gouda_dualsense_usb`。既存のDualSense参照ソースと旧模擬走行ファームウェアは保持しています。PCはUbuntu 24.04 / ROS 2 Jazzyで、GLIM + IMUを使用します。

手動入力があれば両軸とも手動を優先し、自律目標は残します。中立が200 ms続き、センサー・通信が正常なら現在位置から再計算して継続します。手動時にソフトの衝突回避や障害物による減速は行いません。「中止」は自律制御の中止であり、手動操作を無効にするものではありません。

PCからの指令が250 ms途切れるとESP32は自律制御を無効化します。Bluetoothの切断・入力停止でも中立に戻します。通信やセンサー、記録の異常後は開始ボタンを再度操作するまで自動復帰しません。物理非常停止は駆動電源を切る方式との申告で、ソフトへの入力配線は未確認です。本実装に非常停止状態の読戻しはありません。物理停止解除前にはGUIで自律を中止してください。

ソフト試験・ビルドは実機動作の確認ではありません。今回、書込み・USB実機接続・駆動は行っていません。

## 起動

1. 既存手順でPCワークスペースを更新・ビルドします。通常の `bash scripts/gouda.sh view` / `observe` は制御器を開きません。
2. GUIの「記録・SLAM」でGLIM + IMUを選択し、LiDAR・IMU間の位置と向き、時刻・単位設定を保存します。不明値は空欄のまま保存できますが、GLIM開始はできません。
3. 「自動運転MVP」で制御器のUSBポート、車体に対するLiDARの位置・向きを設定し、許可をチェックして保存します。保存操作ではUSBは開きません。
4. `bash scripts/gouda.sh stop` の後、`bash scripts/gouda.sh autonomy` で明示起動します。ホストのLiDAR / IMU接続設定が必要です。GLIMは継続して自己位置を推定します。
5. 目標を現在位置基準の前方m・左m・最終向き度で入力し、要求並進速度m/s・旋回速度rad/sを設定します。正は前進・左旋回です。「記録して自動走行を開始」で記録を確認してから開始要求を送ります。

GUIは受信したPC状態を表示します。「要求を送信」はESP32の開始確認と異なります。設定変更後はプロファイルの再起動が必要です。車椅子本体の「2.5」設定はソフトから変更せず、m/sへ換算しません。

## 取付・車体設定

`$GOUDA_WORKSPACE/bags/gouda/autonomy.json` に保存します。`body_to_lidar` はLiDAR座標を車体座標へ変換する T_body_lidar。車体座標は前X・左Y・上Z、原点は直方体の地面上の幾何中心です。IMU変換はGLIM設定の T_lidar_imu と合成し、二重に別設定を持ちません。

ユーザー提供図面に基づき車体は長さ1.105 m（最大調整時）・幅0.600 m・高さ0.950 mの直方体です。追加LiDAR架台や張り出しは含まないため `footprint` で実際の外形へ変更できます。LiDAR / IMU取付位置・向きは未測定・不明としており、仮のゼロ値で有効化していません。

`controller` は暫定のフィードフォワード・PIゲインです。車体の速度・角速度特性を実測した値ではありません。詳細な特性測定と追加のソフト速度制限は今回行っていません。IMUバイアスも暫定ゼロです。

## センサー追従と障害物

並進速度はGLIMの推定値、角速度はIMUジャイロから求めます。GLIM 1.2.2のlidar_odomの速度はIMU原点・世界座標として扱い、車体座標へ変換し取付位置による速度差を補正します。angular.zのゼロを測定した角速度とは扱いません。前後速度と旋回角速度の誤差をそれぞれ出力へ戻します。

生3D点群を車体へ変換し、直方体の旋回を含む保守的な外接円の掃引領域を確認します。先読みはセンサー推定速度の0.5秒分 + 0.10 mです。制動距離を実測したモデルではなく、衝突しない保証はありません。地上0.04 m未満・設定車体高さより上の点は対象外です。自己反射点を根拠なく消さないため、車体や架台の反射が検出範囲に入る場合も停止します。

## 記録

生LiDAR・生IMU・TFに加え、要求速度、正規化出力、手動入力、ESP32適用値、DACコード、状態、使用設定、センサー時刻を保存します。電圧フィールドは**要求電圧**であり測定電圧ではありません。

主な解析トピックは `/gouda/control/reference`, `/gouda/control/estimate`, `/gouda/control/drive`, `/gouda/control/manual_input`, `/gouda/control_trace`, `/esp32/status`, `/gouda/autonomy/state`。ROS時刻とホスト・機器それぞれの単調時計、機器起動トークン・連番で対応を追えます。両時計が同期しているとは仮定しません。記録終了後、各トピックの件数・欠落がGUIに表示されます。

バッグの再生ではセンサートピックだけを選び、制御トピックを実機ドメインへ再生しないでください。シミュレーション時刻での自律ノード起動は拒否します。

## 検証

`bash scripts/test.sh`：Python回帰試験、既存C++試験、新ESP32コア試験。仮想USB試験は本番C++コアとPCのROSサービス・トピックをパイプで接続し、開始確認・出力・センサー停止によるDISARMを検証します。ハードウェアポートは開きません。

`bash scripts/smoke.sh`：GUI、記録、未設定時の自動開始拒否、RViz独立起動を検証します。

`pio run -d firmware/gouda_dualsense_usb -e esp32dev`：8 MBフラッシュ向けESP32ビルドのみ。アップロードは別操作です。
