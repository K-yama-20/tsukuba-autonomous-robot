# 車体試験（gouda_monitor の /dev タブ）

実車では未実行。表示される値はすべて実測値で、人が確認するまで確定扱いにしない。試験条件の初期値は提案で、`gouda_core/vehicle_tests/motion_start.yaml` にある。

## 動き出しの試験の手順

1. 周囲を空け、平らな床に置く。車輪を浮かせない。電動車椅子に人は乗らない
2. ゲームパッドをつなぎ、すぐ操作できるように持つ。止める手段は、ゲームパッドと車体側の手段。**PC の中立は車体の停止の保証ではない**
3. `bash gouda.sh start`。monitor の運行タブで手動走行、/dev 以外のタブで IMU の受信を確かめる
4. /dev タブを開き、区間を選び、条件を確かめて「実行」。その場の旋回の区間から試すなら「T 解除」だけを選び、方向を 90, 270 にする
5. 始めに中立で静止を記録するので、車体に触らない
6. 終わると「結果」に表が出る。試行を選ぶと波形（指令、DAC、加速度、ヨー）が出る。灰の縦線が区間の始まり、赤の縦線が動き出しの判定
7. 次の試験は Gouda を再起動せず、そのまま「実行」できる（IMU は再起動で固まることがある）

区間の順序は動く距離が小さい順。旋回を先にし、向きを交互にし、動きを検出したらその試行を終える。

方向の角度は 0° が前進、90° が左旋回、180° が後退、270° が右旋回。

遅れの区間は、方向の一覧の順に各方向を 2 回ずつ測る。既定では左 2 回 → 右 2 回 → 前進 2 回 → 後退 2 回（DEC-463、DEC-464）。元の位置の近くに戻すためで、前進と後退の速さが違う分のずれは残る。各方向の 1 回目は前輪が別の方向を向いたまま動き出し、2 回目は前輪がその方向にそろう。試行数は「繰り返し」1 回につき方向ごとに 2 回。

| 区間 | 分かること | 読み方 |
|---|---|---|
| T 解除 | 方向ごとのしきい値 | `below`〜`level` の間に T がある。方向で揃えば円 |
| 遅れ | 指令から動き出しまでの合計 | `mean_s`（継続した動き）、`first_mean_s`（最初の超過、解除の衝撃かもしれない）、`changed_mean_s`（方向を変えた 1 回目の平均）、`same_mean_s`（同じ方向の 2 回目の平均）、`dac_mean_s`（DAC が変わるまで） |
| パルス | 短いパルスで解除待ちから戻るか | `moved_in_pulse`、続く段差の遅れが長ければ `locked` は○ |
| t_lock | 中立何秒でロックするか | 方向（`angle`）ごとに、`locked` が×から○に変わる二つの `gap_s` の間。`moving` は入力の直前に動いていて遅れを読めない回数 |
| T ロック | 走行中に下げてロックする大きさ | 方向（`angle`）ごとに、`locked` が×から○に変わる二つの `level` の間。○は入力の直前に止まっていたこと。`yaw_before` は直前のヨー |

- パルスと t_lock のロックは直接見えないので、続く段差の遅れで判定する。パルスは `full_delay_s` の「ロックとみなす遅れの比」倍以上を○とする。t_lock の基準は方向ごとで、同じ実行の遅れの表、なければその方向の止まっていた最長の中立の遅れ（比べる先が自身なので、その段は必ず○になる）
- 入力の直前に動いていたかは、「基準の窓」の間の IMU で判定する（DEC-466）。旋回はヨーの平均、前後は加速度のばらつきを「検出の倍率」×静止時の σ と比べる。前後の判定は実車で確かめていない
- `first` と `motion` が離れていれば、波形で解除の衝撃かどうかを確かめる
- COMMAND の周期が PRM-14（0.1 s）なので、これより細かいパルス幅は実際には出ない。実際の幅は波形の DAC で見る
- 「軸」が `norm` のときは IMU の TF が得られず、ベクトルの大きさで検出している

自動で終わる場合：モードが手動走行でなくなる。IMU・STATUS が止まったとき、ゲームパッドが優先されたときは中立を出し、戻るまで上限なしで待ってその試行をやり直す（DEC-465。回数は結果の `retries`）。**ゲームパッドを離すと、ESP32 の解除の時間と「試行前の中立」の後に、車体は試験の入力で自動で動き出す。試験を終わらせるには /dev の「中止」を使う。**動き出しを検出した後も「動き出し後の入力の継続」の間は入力を続け、T の最大の段は「T の最大の段の継続」の間続ける。記録は `<data_root>/vehicle_tests/<run_id>/`（meta.json、imu.csv、status.csv、command.csv、events.jsonl、result.json）。

## 試験の足し方

1. `gouda_core/gouda_core/vehicle_tests/<id>.py` に `build_trials(params)` と `analyze(run, params)` を書く。`analyze` の `tables` がそのまま画面の表になる
2. `gouda_core/vehicle_tests/<id>.yaml` に条件を書く。画面の入力欄はここから作られる
3. `vehicle_tests/__init__.py` の `TESTS` に 1 行足す
